# Review checklist

Mark each item Pass, Fail or Not applicable. Every Fail becomes a finding with a fix.

## Blockers if failed

- [ ] Every irreversible or high-impact action needs explicit approval, never a default.
- [ ] A running task can be stopped, and stopping leaves things in a known state.
- [ ] People can tell which actions the agent took, everywhere those actions show up.
- [ ] Messages or content the agent sends as the person are previewed before sending.

## Before

- [ ] Scope is shown in plain words: what the agent can read and what it can do.
- [ ] For multi-step work, the plan is visible before it starts and can be changed.
- [ ] The agent's understanding of the task is echoed for anything that matters.

## During

- [ ] Progress is real (steps or counts), not just a spinner, for anything over a few seconds.
- [ ] Questions are specific, with options and a default.

## After

- [ ] A receipt lists what changed, with links to the real items.
- [ ] Reversible actions offer undo, with the window stated.
- [ ] An activity log keeps a durable history.

## When unsure or failing

- [ ] Uncertainty is stated with its reason; sources are shown for factual claims.
- [ ] Partial completion says what worked, what failed and what state things are in.
- [ ] Error states answer: what happened, what changed, what next.

## Leaving

- [ ] A route to a person exists, with context handed over.
- [ ] Memory is visible, editable and optional.

## Words

- [ ] Buttons name the action and the number of items.
- [ ] Outcomes say what was done and what was not.
- [ ] No fake feelings, no exclamation marks on outcomes, no over-promising.

## Load

- [ ] In a typical session, routine approvals are few enough that people still read them.
